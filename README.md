# Mic-Bot 中央控制服务器

这是一个功能强大的、容器化的API服务与前端面板，旨在作为 `mic-bot` 分布式执行节点的中央指挥与控制（C2）服务器。它通过安全的、基于Token的API接收来自不同节点的任务状态，将所有配置和监控数据集中存储在PostgreSQL数据库中，并最终通过一个基于LayUI的、美观优雅的Web界面进行统一的管理、监控和任务下发。

## ✨ 核心特性

* **集中化管理**: 通过统一的Web界面，对所有节点、账户、推送进行增、删、改、查操作。
* **多节点架构**:
    * 支持同时管理多个 `mic-bot` 执行节点。
    * 通过为每个节点生成唯一的、经过哈希存储的 **API Token**，实现了安全认证和数据隔离。
* **远程节点配置**:
    * 在网页上即可为每个 `mic-bot` 节点独立配置所有运行参数，包括**定时任务 (Cron)**、**并发数**、**随机延迟**和**搜索间隔**。
* **实时状态监控**:
    * **节点监控**: 实时查看每个节点的**在线/离线**状态、**IP地址**、**账户负载**以及当前是**"运行中"还是"待机"**。
    * **账户监控**: 在监控面板和账户管理页，都能以清晰的图标和卡片，查看每个账户在**桌面端**和**移动端**的详细登录状态。
* **智能日志管理**:
    * **日志推送**: 支持节点主动推送日志到服务端，实现集中化日志管理。
    * **实时日志查看**: 在节点管理页面可直接查看每个节点的实时日志，支持按级别、标题过滤。
    * **日志存储**: 所有节点日志统一存储在数据库中，支持历史查询和清理。
* **灵活的任务调度**:
    * 支持基于每个节点配置的 **Cron 表达式**进行自动化任务调度（未来可扩展）。
    * 支持在节点管理页面对任意**在线且待机**的节点，进行**手动触发**和**紧急停止**操作。
* **全局推送中心**:
    * 在独立的"推送配置"页面，集中管理所有 **Bark** 推送URL。
    * 可为每个URL独立订阅"节点上线"、"节点离线"、"账户异常"等关键事件。
* **验证码管理**:
    * 支持Node端和Service端之间的验证码传递功能。
    * 提供验证码管理页面，支持手动输入验证码。
    * 自动处理验证码过期和清理。
* **移动端积分查看**:
    * 提供免登录的移动端积分查看页面。
    * 支持节点分组显示和状态徽章标识。
    * 响应式设计，完美适配移动端设备。
* **健壮的技术栈**:
    * **后端**: Python + Flask (应用工厂模式)
    * **数据库**: PostgreSQL (通过 SQLAlchemy ORM 操作)
    * **前端**: LayUI 框架
    * **部署**: Docker, Docker Compose

## 🚀 部署与初始化

部署指挥中心是一个一次性的过程，请严格按照以下步骤操作：

### 1. 准备环境
* 一台拥有公网IP的服务器。
* 已安装 [Docker](https://get.docker.com/) 和 [Docker Compose](https://docs.docker.com/compose/install/)。

### 2. 下载并配置项目
* 将本项目的全部文件上传到您服务器的一个目录中（例如 `/root/mic-bot-service`）。
* 打开 `docker-compose.yaml` 文件，根据您的需要修改 `db` 服务中的 `POSTGRES_...` 环境变量，特别是 **`POSTGRES_PASSWORD`**，请务必修改为一个强密码。

### 3. 构建并启动服务
* 在项目根目录下，执行以下命令来构建和启动所有服务：
    ```bash
    docker-compose up -d --build
    ```
* 首次启动时，请等待约30-60秒，让PostgreSQL服务完成初始化。

### 4. 初始化数据库
首次启动时，系统会通过 `init/init_fixed.sh` 脚本自动完成数据库初始化，包括创建必需的数据表和版本记录。无需手动执行命令。

### 5. 创建您的管理员账号
数据库初始化完成后，您可以通过网页注册功能创建第一个管理员账号：
1. 访问 `http://你的服务器IP:2002/register`
2. 填写用户名、密码（请确保足够复杂）和邮箱
3. 点击注册按钮完成账号创建
4. 系统会自动将第一个注册的用户设置为管理员权限

### 6. 登录并开始使用
* **访问网页**: 打开浏览器，访问 `http://你的服务器IP:2002`。
* **登录**: 使用您通过注册创建的管理员用户名和密码进行登录。
* **开始配置**:
    1. 导航到"**节点管理**"页面，创建一个新节点以获取 API Token。
    2. 导航到"**推送配置**"页面，添加您的 Bark URL 并订阅您关心的事件。
    3. 导航到"**账户管理**"页面，开始添加和分配您的 `mic-bot` 账户。

## 🔄 数据库版本管理

系统包含自动数据库版本管理功能，可在升级时自动应用数据结构变更。

### 版本管理原理
1. 系统使用 `db_version` 表记录数据库结构版本
2. 每次启动服务时，`init/init_fixed.sh` 脚本会检查当前数据库版本
3. 如果发现有新版本的升级脚本需要应用，会自动执行并记录新版本

- **v2.4**: 为bot_accounts表添加created_at字段

### 创建新的升级脚本
当需要修改数据库结构时，请按照以下步骤操作：
1. 创建新的升级脚本 `sql/upgrade_db_vX.Y.sql`
2. 在新脚本中添加你的SQL变更语句，使用安全的 `DO $$ IF NOT EXISTS $$` 语法
3. 在脚本中添加版本记录语句，例如：
   ```sql
   INSERT INTO db_version (version, description) VALUES ('X.Y', '变更描述');
   ```

### 手动执行升级
如果需要手动执行升级，可以使用以下命令：
```bash
docker-compose exec api python init/upgrade_db.py upgrade-db
```

## 🔐 验证码管理功能

### 验证码流程
1. **Node端流程**：
   - 遇到需要验证码的登录页面
   - 自动填入辅助邮箱并点击发送
   - 调用Service端API创建验证码请求
   - 循环检查验证码状态（每3秒一次）
   - 显示倒计时日志：`等待验证码输入...300s`
   - 收到验证码后自动填入并继续流程

2. **Service端流程**：
   - 接收Node端的验证码请求
   - 在验证码管理页面显示待处理的验证码
   - 管理员输入验证码
   - 将验证码传递给对应的Node端
   - Node端收到验证码后继续执行

### 验证码管理页面
- **主账户**: Node端正在执行任务的主账户邮箱
- **节点名称**: 处理该账户的节点
- **辅助邮箱**: 用于接收验证码的辅助邮箱
- **创建时间**: 验证码请求的创建时间
- **过期时间**: 验证码的过期时间
- **剩余时间**: 倒计时显示剩余时间

## ⚡ 性能优化

### 数据库查询优化
- **N+1查询优化**: 使用子查询一次性获取所有统计数据
- **预加载优化**: 预加载所有User-Agent映射，使用JOIN查询
- **批量查询优化**: 批量获取所有待执行任务，在内存中分组处理

### 缓存机制
- **内存缓存**: 简单的内存缓存，30秒过期
- **缓存清理**: 数据更新时自动清除相关缓存

### 数据库索引优化
- `idx_accounts_bot_account_id`: 账户监控数据关联查询
- `idx_accounts_last_updated`: 按时间排序查询
- `idx_tasks_node_status_time`: 任务查询复合索引
- `idx_node_logs_node_timestamp`: 日志查询复合索引
- `idx_user_agents_used_by_account`: User-Agent 关联查询

### 性能提升效果
- **页面加载时间**: 从 3-5秒 降低到 0.5-1秒
- **数据库查询次数**: 减少 70-80%
- **内存使用**: 增加约 10-20MB（缓存开销）

## 💰 积分计算优化

### 积分计算流程
```
初始积分 (1000)
    ↓
桌面端任务执行
    ↓
桌面端完成积分 (1200) → 桌面端收益 = 1200 - 1000 = 200
    ↓
移动端任务执行 (基于桌面端完成后的积分)
    ↓
移动端完成积分 (1350) → 移动端收益 = 1350 - 1200 = 150
    ↓
总收益 = 1350 - 1000 = 350 (或 200 + 150 = 350)
```

### 优势
- **避免重复计算**: 桌面端和移动端收益独立计算
- **准确统计**: 能够准确区分各端的实际收益
- **逻辑清晰**: 计算流程更加清晰易懂
- **数据一致**: 确保总收益等于各端收益之和

## 🐛 故障排除

### 常见问题
1. **页面无法访问**
   - 检查服务是否正常运行
   - 确认端口2002是否开放

2. **数据库连接失败**
   - 检查PostgreSQL容器状态
   - 确认数据库密码配置正确

3. **验证码功能异常**
   - 检查时区设置
   - 确认辅助邮箱配置正确

4. **性能问题**
   - 检查数据库索引是否创建
   - 查看慢查询日志

### 调试方法
1. **查看服务日志**
   ```bash
   docker-compose logs api --tail=50
   ```

2. **检查数据库状态**
   ```bash
   docker-compose exec db psql -U user -d rewards_db -c "SELECT version FROM db_version ORDER BY applied_at DESC LIMIT 1;"
   ```

3. **测试API接口**
   ```bash
   curl http://localhost:2002/web_api/mobile/get_points
   ```

# 搜索任务交叉执行流程图

## 整体执行流程

```
开始执行任务
    ↓
检查配置是否启用交叉执行
    ↓
┌─────────────────────────────────────┐
│ 配置未启用交叉执行                    │
│ ↓                                  │
│ 使用顺序执行模式                      │
│ ↓                                  │
│ 结束                               │
└─────────────────────────────────────┘
    ↓
检查账户数量是否 >= 2
    ↓
┌─────────────────────────────────────┐
│ 账户数量 < 2                        │
│ ↓                                  │
│ 使用顺序执行模式                      │
│ ↓                                  │
│ 结束                               │
└─────────────────────────────────────┘
    ↓
预检查所有账户登录状态
    ↓
┌─────────────────────────────────────┐
│ 有效登录账户 < 2                     │
│ ↓                                  │
│ 使用顺序执行模式                      │
│ ↓                                  │
│ 结束                               │
└─────────────────────────────────────┘
    ↓
启用交叉执行模式
    ↓
执行交叉搜索任务
    ↓
结束
```

## 详细交叉执行流程

### 1. 预检查阶段

```
开始预检查
    ↓
┌─────────────────────────────────────┐
│ 遍历所有账户                        │
│ ↓                                  │
│ 创建浏览器实例                      │
│ ↓                                  │
│ 访问 https://rewards.bing.com       │
│ ↓                                  │
│ 检查登录状态指示器：                  │
│ • 用户头像和账户信息元素              │
│ • 注销链接                          │
│ • 积分信息                          │
│ • 活动相关元素                      │
│ • 页面标题                          │

统计有效登录账户数量

```

## 场景示例

### 场景1：3个账户，2个已登录，1个未登录

```
预检查结果：
├── 账户A：已登录 ✅
├── 账户B：已登录 ✅  
└── 账户C：未登录 ❌

判断结果：有效登录账户 >= 2，启用交叉执行模式

交叉执行过程：
第1轮桌面端：
├── 账户A：跳过登录 → 执行搜索任务
├── 账户B：跳过登录 → 执行搜索任务
└── 账户C：执行登录 → 执行搜索任务

第1轮移动端：
├── 账户A：跳过登录 → 执行搜索任务
├── 账户B：跳过登录 → 执行搜索任务
└── 账户C：执行登录 → 执行搜索任务
```

### 场景2：3个账户，只有1个已登录

```
预检查结果：
├── 账户A：已登录 ✅
├── 账户B：未登录 ❌
└── 账户C：未登录 ❌

判断结果：有效登录账户 < 2，使用顺序执行模式

顺序执行过程：
├── 账户A：跳过登录 → 执行所有任务
├── 账户B：执行登录 → 执行所有任务
└── 账户C：执行登录 → 执行所有任务
```

### 场景3：1个账户

```
预检查结果：
└── 账户A：已登录 ✅

判断结果：账户数量 < 2，使用顺序执行模式

顺序执行过程：
└── 账户A：跳过登录 → 执行所有任务
```

## 关键决策点

### 决策点1：是否启用交叉执行
```
条件检查：
1. 配置是否启用交叉执行？
2. 账户数量是否 >= 2？
3. 有效登录账户数量是否 >= 2？

结果：
- 所有条件满足 → 启用交叉执行模式
- 任一条件不满足 → 使用顺序执行模式
```

### 决策点2：单个账户登录状态
```
登录状态检查：
1. 访问 Microsoft Rewards 页面
2. 检查多种登录指示器
3. 判断是否已登录

结果：
- 已登录 → 跳过登录步骤，直接执行搜索任务
- 未登录 → 执行完整登录流程，然后执行搜索任务
```

## 错误处理和重试机制

### 任务失败处理
```
单个账户任务失败：
├── 记录失败原因
├── 继续执行下一个账户
└── 在轮次结束后重试失败任务

轮次失败处理：
├── 检查是否有失败任务
├── 如有失败，继续下一轮
└── 达到最大轮数限制时停止
```

### 登录失败处理
```
登录失败：
├── 记录登录失败原因
├── 标记账户为失败状态
├── 继续执行其他账户
└── 在重试阶段再次尝试登录
```

## 性能优化

### 预检查优化
```
预检查阶段：
├── 使用轻量级浏览器实例
├── 设置合理的超时时间（30秒）
├── 快速检查登录状态
└── 及时释放浏览器资源
```

### 交叉执行优化
```
交叉执行阶段：
├── 按账户轮询，确保公平性
├── 设置轮次间延迟（2秒）
├── 限制最大轮数（10轮）
└── 支持中途停止指令
```
